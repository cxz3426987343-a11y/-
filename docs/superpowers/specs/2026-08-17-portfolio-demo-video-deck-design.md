# 个人作品集 90 秒 Demo 视频与演示文档设计

## 目标

为陈薪竹现有个人作品集网站制作一套面向招聘者的轻量展示资产。招聘者应在约 1 分钟内理解候选人的定位、完整能力链路、代表经历和四类作品，并可在 90 秒内看完完整 Demo。

本次不修改网站代码、视觉设计、交互行为、作品顺序或线上功能。所有录制、剪辑、演示文档和二维码文件均作为独立交付物保存。

- 主要受众：内容运营、用户运营、培训运营、品牌传播、策划及相关岗位的招聘者。

- 观看环境：电脑、微信聊天窗口、常见手机播放器；视频即使静音播放，也能通过字幕完整理解。

## 视频规格

- 时长：90 秒，允许最终编码误差不超过 0.5 秒。
- 画幅：16:9 横屏。
- 分辨率：1920 x 1080。
- 帧率：30 fps。
- 视频编码：H.264。
- 音频编码：AAC，48 kHz。
- 兼容目标：Chrome、Edge、Safari、微信常见视频预览和 Windows/macOS 本地播放器。
- 视觉来源：已部署网站的真实页面与真实交互，不重绘网站界面。
- 字幕：简短中文主字幕；专业名词和页面原有英文保留，不添加大段说明。
- 音频：轻量、克制的无歌词音乐。作品视频出现时背景音乐压低，保留约 2 秒原声。

## 剪辑语言

- 以真实页面录屏为主体，使用干净切换、缓动缩放和少量遮罩过渡，不添加模板化粒子或与网站无关的装饰。
- 鼠标轨迹保持稳定，点击动作清楚但不夸张。
- 页面滚动速度以内容可辨认为准；不使用会让文字无法阅读的高速滚动。
- 字幕放在不遮挡页面核心信息的位置，并保持网站原有黑、白、绿色体系。
- 网站已有动画是重点，后期不重复叠加同类效果。
- 结尾二维码周围保留高对比净空区，避免动画或文字穿过定位图形。

## 生成流程

1. 以 1920 x 1080 浏览器视口录制每个页面的指定交互片段。
2. 逐段检查页面文字、图片加载、视频画面、声音和动效是否完整。
3. 按分镜剪辑到 90 秒，加入字幕、音乐和音量压低处理。
4. 导出 H.264/AAC MP4，并在本地播放器和浏览器中复核。
5. 上传最终 MP4 到 Vercel Blob，确认公共链接无需登录即可播放。
6. 根据最终 Blob 地址生成 PNG 和 SVG 二维码，并用实际扫码/解析验证目标链接。
7. 从网站录制画面中选择清晰截图，制作 10 页 PPT。
8. 渲染检查每一页 PPT，修复溢出、遮挡、模糊和比例错误。
9. 导出同版式 PDF，逐页渲染检查。

## 验收标准

### 视频

- 总时长 89.5-90.5 秒。
- 1920 x 1080、30 fps、H.264/AAC。
- 画面无浏览器错误页、加载占位、登录提示、水印或鼠标误操作。
- Hero、抽卡、图片环绕、电影票播放、文件夹弹纸、手机解锁和 ID 卡流光均出现。
- 字幕无错别字、无裁切、无重叠，并可在静音状态下理解。
- 本地 MP4 与 Blob 版本内容一致。

### 二维码

- PNG 和 SVG 均能解析为同一个 Blob MP4 地址。
- 手机扫描后无需登录，可直接打开视频。
- 二维码在最终 PPT/PDF 和独立文件中均清晰可扫。

### PPT/PDF

- 均为 10 页、16:9 横屏，顺序和内容一致。
- PPT 无元素溢出、意外重叠、标题换行或低清晰度截图。
- PDF 每页可正常渲染，无黑块、缺字、乱码或裁切。
- 所有图片保持正确比例，所有脱敏内容维持脱敏。

## 失败处理

- 若页面资源未加载完成，放弃该录制片段并重新录制，不在后期用静态占位替代。
- 若线上视频加载不稳定，先确认 Blob 地址和浏览器媒体状态；录制片段仍必须来自网站真实播放器。
- 若字体在 PPT/PDF 导出时替换或乱码，改用本机可用且支持中文的字体，并重新渲染全部页面。
- 若 Blob 链接发生变化，重新生成两种二维码，并同步替换 PPT/PDF 中的二维码后再交付。
